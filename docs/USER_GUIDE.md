# StudyAgent 使用指南

本指南适用于当前仓库的本地版本，面向第一次安装的同学、日常学习者和协作测试的队友。StudyAgent 将课程资料、阅读位置、批注、提问、知识卡片和学习记录保存在本机；AI 问答可按需连接外部模型。

> 推荐先完成一次最短流程：启动服务 → 注册本地账号 → 新建课程 → 上传一份讲义 → 阅读并批注 → 选择模型提问 → 结束学习 → 到“笔记 / 知识库 / 复习”查看结果。

## 1. 安装与启动

### 1.1 准备环境

- 安装 **Node.js 22.5 或更新版本**，并确认命令行可运行 `node --version`、`npm --version`。
- 建议在 Windows 上使用 PowerShell；其他系统可在终端运行相同的 npm 命令。PDF 页面图片及部分 OCR 功能依赖本机的 Poppler 工具（例如 `pdftoppm`）；若系统缺少该工具，相应能力可能不可用。
- 下载或克隆仓库：[ruxuanwang2-maker/studyagent](https://github.com/ruxuanwang2-maker/studyagent)。**GitHub 仓库不包含个人数据库、上传资料及模型密钥**，每位队友需自行导入测试资料。

在项目根目录执行：

```powershell
npm install
npm start
```

终端出现 `StudyAgent running at http://127.0.0.1:4173` 后，在浏览器打开 <http://127.0.0.1:4173/>。首次安装依赖需要网络；以后正常启动使用本地地址。可以访问 <http://127.0.0.1:4173/api/health> 检查服务：正常结果包含 `"ok":true` 和数据库类型 `"sqlite"`。

Windows 还可在完成一次 `npm install` 后双击根目录的 `启动 StudyAgent.cmd`。如果浏览器先于服务打开而显示连接失败，稍等片刻再刷新。关闭运行服务的终端后，网页也会停止响应。

### 1.2 数据库选择

默认使用项目目录下的 `data/studyagent.sqlite`，**无需安装 MySQL，也无需创建 `.env`**。需要使用 MySQL 的团队部署可复制 `.env.example` 为 `.env`，把 `STUDYAGENT_DB` 改为 `mysql` 并填写连接参数。两个数据库之间不会自动搬运个人数据；普通单机使用保持默认设置即可。

## 2. 账号与数据

1. 点击侧边栏“账号”。
2. 在注册区填写**本地登录名**和密码（至少 8 位），点击“注册”。新账号不需要邮箱验证码。
3. 以后使用相同的登录名和密码登录。历史版本创建的邮箱账号仍可使用原邮箱登录；如果输入框仍写着 `Email`，新账号也应输入自己的本地登录名。
4. 账号页可修改显示名称、修改密码、导出自己的数据、退出登录或删除账号。

游客模式可用于临时体验，但不适合保存长期学习记录。登录后，课程、资料、对话、批注、笔记、图谱和模型配置按账号隔离。**删除账号会删除该账号的学习数据**；操作前先使用账号页的“导出我的数据”。

## 3. 课程和资料导入

### 3.1 建立课程

1. 进入侧边栏“课程”，点击“新建课程”。
2. 输入课程名称，例如“数值线性代数”，点击“创建课程”。
3. 在课程页面可查看该课程的资料；资料列表中的课程选择框可调整已有文件的归属。

课程用于限定检索范围。向某门课程提问时，优先选择正确的课程，以免混入其他课程的资料。

### 3.2 上传资料

1. 进入“资料库”，先在上传按钮旁选择目标课程；不选择则归入“未分类”。
2. 点击“上传”并选取一个或多个文件。导入完成后，文件出现在资料库中；点击卡片进入阅读器。
3. 若文件较大或需要 OCR，等待导入状态完成。导入失败时查看页面提示，检查文件格式、体积和本机解析工具。

目前接受：PDF、DOCX/DOC、PPTX/PPT、MD、TXT、XLSX/XLS、CSV、PNG、JPG/JPEG、WEBP。DOCX、PPTX、XLSX 能保留可提取的标题、段落、表格、幻灯片、备注、工作表等结构。旧版二进制 DOC/PPT/XLS 若没有 LibreOffice/`soffice`，建议先在 WPS 或 Office 中另存为 DOCX/PPTX/XLSX。对 Word 等非 PDF 文件，阅读页是解析后的结构化页面，**不保证与 WPS 的原生分页完全一致**。

资料库也支持按课程或自定义集合整理文件；集合用于视图组织，不改变文档所属课程。

## 4. 阅读、公式与批注

### 4.1 浏览讲义

- 在“资料库”点击文件，或从首页“继续阅读”进入。
- PDF 默认以保留原始排版的连续页面显示，滚动即可阅读；工具栏可翻页、缩放，并在原始 PDF 与解析视图之间切换。解析视图用于查看提取的文字、表格、OCR 文本和公式候选。
- Word、PPT 等以连续的结构化阅读页显示。页码提示会随着阅读位置更新；重新进入资料会尝试恢复上次停留页。
- 有疑问时以**原始 PDF 或原文件**核对排版和公式，不应把 OCR 候选视为权威原文。

### 4.2 选择内容并操作

在可选文字区域拖动选择一段内容，或在解析视图点击公式旁的“选择公式并提问”。浮动工具栏可用于解释、详细推导、追问原因、关联历史、生成题目、高亮、知识卡和笔记。选择公式时，系统会把对应 LaTeX 随问题传递给 AI。取消选择可点击阅读区空白处或按 `Esc`。

对于 PDF 中无法直接选中的公式或图表，点击工具栏“框选提问”，拖动框出区域，检查预览并输入问题后发送给**支持视觉的模型**。这项操作会把框选图片发给所选模型服务；若尚未配置视觉模型，先到“设置”完成配置。区域截图提问目前针对 PDF 原始页面。

### 4.3 高亮、笔记与结束学习

- 高亮：选中文字或公式后点击“高亮”，刷新后仍可在该文档看到已保存的批注。
- 笔记：选择内容后点击“笔记”，写下自己的理解、疑问或考试重点；也可以在“笔记”页新建独立笔记。笔记支持编辑、删除和从来源按钮返回文档页。
- 结束学习：点击阅读器工具栏的“结束学习”。系统根据本次访问页、批注和问题保存学习会话、学习笔记及学习经历。随后到“笔记”的学习记录或“知识库”查看，不要把“浏览过”理解成“已经掌握”。

### 4.4 OCR 与公式核对

扫描 PDF 和图片使用本地 OCR；数学公式会尝试生成 LaTeX 并在界面中显示为可视公式。复杂公式可能识别错误。需要更高质量的单页重识别时，可在“设置 → 专用数学 OCR”填写自己的 Mathpix App ID 和 App Key，然后在阅读器**解析视图**点击“使用专用数学 OCR 重识本页”。这是外部服务调用，可能产生费用；重识别后仍需对照原页人工核查。

## 5. 配置 AI 模型并提问

### 5.1 添加模型

1. 进入“设置 → AI 模型设置”，选择 Provider（例如 DeepSeek、OpenAI、Gemini、通义千问或 Ollama）。
2. 检查模型名称和自动填入的 Base URL；自定义兼容服务可修改地址。输入该服务商的 API Key。Ollama 不需要 Key，但本机必须启动 Ollama 及所选模型。
3. 点击“保存配置”，再点击“测试连接”；出现成功提示后，在阅读器右侧的 **AI Model** 下拉框选择该模型。需要作为默认模型时勾选 `Default model` 后保存。
4. 发出一个不含敏感资料的简短测试问题，确认回答区域展示预期 Provider/模型以及引用来源。模型连接测试不等于复杂问题的回答质量测试。

模型密钥保存在本地服务端的加密配置中，界面只显示掩码。不要把 Key 写入 README、源码、截图、聊天记录或 Git 提交。选择外部 Provider 时，当前问题及所选范围内的必要上下文会发送给该服务商；个人或受限资料请先确认可否外发。

### 5.2 提问和引用

- 阅读时可在右侧“对话”输入问题，例如：“这一步为什么需要选主元？请引用当前页。”
- 先检查“上下文范围”：当前页面、当前文件、当前课程、指定文件或整个知识库。选择“指定文件”时，还需在文件列表中选定目标；选择课程范围时先选课程。
- 可以选中正文或公式后提问，系统会携带该段文字、文档和位置；连续追问时保留当前对话上下文。
- 回答下方的来源引用可点击，跳回对应资料与页码。引用和数学公式仍应由学习者核对，尤其是扫描件和复杂推导。
- 如果下拉框为“仅本地证据检索（非大模型）”，系统提供资料检索/证据类结果，不能期待完整的开放式推导。已选远程模型调用失败时，应检查报错、Key、额度和网络；不要把本地证据摘要当成该模型的回答。

阅读器的“摘要”标签可生成本页摘要；本地模式会标为**本地证据摘要**，已配置模型的结果会标为 AI 页面摘要。

## 6. Prompt 优化、上下文与隐私

在“设置 → Prompt 优化与记忆增强”中可以调整：

- **优化级别**：关闭、自动或始终优化；自动适用于需要补充指代和学习背景的问题。
- **回答模式**：快速回答、详细解释、学习模式、考试模式、苏格拉底模式。
- **优化模型 / 最终回答模型**：两者可分别选择；不配置优化模型时使用本地结构化优化。
- **上下文来源**：可选择长期记忆、当前资料、近期对话和知识关联。
- **提问前预览**：启用后可查看和编辑优化后的内部 Prompt，再选“使用原始问题”或“使用优化 Prompt”。

原始问题仍保留；优化器不应替你改变真实提问意图。阅读器的“将本次提问保存到长期记忆”复选框可控制该轮是否写入长期记忆。“设置”还可选择中文/English、上下文发送范围和检索条数。开发日志与 Agent Context Inspector 仅用于调试，正常学习不必开启。

## 7. 知识卡片、笔记与复习

### 7.1 生成和管理卡片

在阅读器选中知识点、例题或公式后点击“知识卡”；也可以在“知识库”打开“生成知识卡片”。填写分类和学习内容后保存。卡片会记录来源，可从卡片返回原讲义。

知识库支持按分类查看、修改卡片分类、重命名分类、移除分类以及删除单张卡片。**移除分类会把其中卡片移入“未分类”，删除卡片才会删除卡片本身**；原讲义不会随卡片删除。生成后检查标题、公式和步骤，低质量 OCR 来源尤其需要回原页核对。

### 7.2 复习和自测

在“复习”页按课程打开知识卡，先独立回忆，再展开答案。页面还可点击“生成 6 道多样题”；题目根据资料检索证据形成，常见类型包括概念解释、证据阅读、比较辨析、应用推理和错误诊断。先作答再展开答案及来源。

这些题目主要用于主动回忆；当前系统**没有独立的自动判题器**。题目或答案中的 OCR 公式若无法核实，应打开来源页比对。知识库展示提问、自评、错误等可核对的学习证据，不把阅读次数或一个“掌握百分比”当作能力测量。

## 8. 学习记忆、知识图谱与数据导出

- “知识库”展示概念、卡片、阅读记录和知识图谱；点击概念可查看相关来源、历史问题和学习证据。
- “设置 → 学习偏好与长期记忆”可编辑回答风格、公式表达、学习目标和编程语言偏好，查看/编辑/删除长期记忆，并导出记忆。历史提问与学习证据可在相关页面查看。
- “笔记”页汇集手动笔记和学习经历；可以按来源返回讲义。
- “账号”页的“导出我的数据”用于导出当前账号数据。计划迁移电脑、重装系统或删除账号前，应分别备份账号导出文件及本地运行数据。

本地主要数据位于 `data/`，上传原文件位于 `uploads/`。两者都被 `.gitignore` 排除，**推送 GitHub 不会同步个人资料或 API Key**。备份 SQLite 时先停止 StudyAgent 服务，再复制数据库及相关资料文件，避免运行中的数据库状态不一致。

## 9. 建议的完整学习流程

以下例子可用于首次体验，也可给队友做人工回归：

1. 创建并登录自己的本地账号。
2. 新建“数值线性代数”课程，上传一份 PDF 讲义，确认资料库能打开文件并显示页码。
3. 阅读第一页，选一句定义做高亮，再写一条“为什么需要这个条件？”的笔记。
4. 选中一个公式；若无法选择，改用 PDF 的“框选提问”，并先确认视觉模型已配置。
5. 在右侧选择模型与“当前页面”范围，问“这个公式每个符号是什么意思？”，再追问“给一个例子”。检查引用是否能返回原页。
6. 从选中内容生成知识卡，检查分类、来源和公式展示。
7. 点击“结束学习”，打开“笔记”查看本次学习记录；到“知识库”查看概念和图谱，再进入“复习”生成题目。
8. 退出并重新登录，重新打开讲义，检查上次页码、批注、笔记和历史提问是否仍可访问。

## 10. 常见问题

| 现象 | 先检查什么 | 建议操作 |
| --- | --- | --- |
| `127.0.0.1:4173` 无法访问 | 运行服务的终端是否还在；`/api/health` 是否响应 | 回到项目根目录运行 `npm start`；若端口被占用，先找出正在运行的旧服务 |
| 已填 API Key，回答仍显示“本地证据” | 是否“保存配置”“测试连接”，阅读器 **AI Model** 是否选择新配置 | 选中配置后再提问；若测试失败，核对 Provider、模型名、Base URL、Key 与额度 |
| 模型请求显示网络错误、超时或无权限 | 本机联网、服务商状态、Key 权限和模型名称 | 到设置页重新“测试连接”；阅读具体错误，勿在群聊公开 Key |
| 上传后文字或公式乱码 | 是否为旧版错误导入记录；原文件是否为扫描件 | 用原 PDF 核对；必要时重新上传原文件，对单页尝试专用数学 OCR 并人工校正 |
| 旧版 `.doc`、`.ppt`、`.xls` 无法完整解析 | 是否安装 LibreOffice/`soffice` | 用 WPS/Office 另存为 `.docx`、`.pptx`、`.xlsx` 后重新导入 |
| 资料存在，但提问或自测没有可用证据 | 文档是否导入完成；课程/文件范围是否选错 | 查看导入状态，切到正确课程或当前文件；确保该页有可提取内容 |
| 笔记/记忆在另一浏览器或账号看不到 | 是否登录了相同账号；是否仍在游客模式 | 进入“账号”确认登录名；不同账号的数据彼此隔离 |
| 卡片中的公式不准确 | 来源是否为 OCR 候选，原文能否核对 | 返回来源讲义核查；必要时修正识别结果后重新生成 |

## 11. 团队协作与测试

- 每位队友从 GitHub 获取项目，运行 `npm install` 和 `npm start`，用自己的本地账号和测试文件操作。不要提交 `data/`、`uploads/`、`.env`、API Key 或个人讲义。
- 改动前先查看 [README](../README.md) 与[架构说明](ARCHITECTURE.md)；提交前至少运行 `npm run check:syntax` 和与改动相关的专项检查。
- 全套回归命令为 `npm run verify`。其中桌面讲义回归默认读取 `Desktop/讲义`，**自动排除其中最大的文件**；其他电脑没有该目录时，可设置 `STUDYAGENT_LECTURE_DIR` 指向自己的测试资料文件夹。全套回归会进行真实本地导入和清理，运行前先确认测试目录内容适合用于回归。
- 第三方模型的实网效果需要在各自账号下单独验证；本地协议检查与语法检查不能证明外部服务当时可用。

如需了解 API、数据库和已知限制，继续阅读 [AI 请求链路](AI_PIPELINE.md)、[数据库结构](DATABASE_SCHEMA.md)、[回归计划](TEST_PLAN.md) 与[安全说明](SECURITY_REVIEW.md)。
